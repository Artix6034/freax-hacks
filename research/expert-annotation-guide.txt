Инструкция по пустым экспертным формам DEV

Это формы для ручного заполнения, не Ground Truth и не AI-оценки. Исходный исследовательский документ: research/cqa-methodology.txt; текущие факты о данных: research/dev-review-brief.txt. Правила берутся из выданного PDF, спорные толкования не становятся официальными автоматически.

Файлы pilot20-expert-a.blank.jsonl и pilot20-expert-b.blank.jsonl содержат по 20 записей, holdout10-expert-a.blank.jsonl и holdout10-expert-b.blank.jsonl — по 10. Одна строка JSONL = один диалог и восемь критериев. Все оценки, объяснения и итог изначально пустые. Для работы создать отдельную локальную копию; исходную пустую форму и исходные оценки не перезаписывать.

1. Эксперты A и B оценивают независимо, до просмотра AI-ответов и ответов друг друга. Заполнить annotator_id и annotated_at, сохранить transcript_hash и версию чек-листа. Для отложенного набора не передавать разметку в контур настройки; открыть его для проверки только после фиксации метода.
2. У каждого критерия value заполняется только разрешённым yes/no/na или числом. null означает «ещё не размечено», а не отрицательный ответ, ноль или N/A. Для 08 yes = обнаружено грубое нарушение, баллов он не даёт.
3. explanation связывает наблюдение с конкретным правилом. evidence: message_id, дословный quote и краткий supports. При необходимости нескольких реплик указать каждую. Для пропуска действия checked_ranges: from_message_id, to_message_id, expected_action; нельзя сочинять цитату отсутствия.
4. Для N/A заполнить na_reason: condition_id, explanation, evidence_message_ids. Разрешённые condition_id: enough_information_initially для 02; identification_not_required для 03; ended_before_request для 04; interrupted_before_closing_opportunity для 07. Для иных критериев N/A запрещён. Неуверенность не является основанием N/A.
5. Если правило или факт неоднозначны, записать конкретный вопрос в uncertainties, needs_adjudication=true, annotation_status=needs_adjudication. Не заставлять null выглядеть как завершённую эталонную метку. Допустимая предварительная метка эксперта может быть сохранена вместе с флагом спорности, но не включается в «согласованный эталон» без разбора.
6. При завершённой независимой разметке annotation_status=annotated, reference_kind=provisional_human_annotation. Это внутренняя экспертная оценка, не официальный GT организаторов. Итог рассчитывается отдельно из меток по правилам; manual total_score не использовать для подгонки критериев.
7. Сопоставить A/B по каждому критерию и применимости. При разногласии сохранить обе исходные оценки, решение проверяющего и причину отдельной ревизией. Финальный provisional reference — результат разбора, а не среднее баллов двух экспертов.
8. Для проверки ссылок используется data/dev/indexed-transcripts.jsonl. m0001 — первый элемент исходного массива, включая bot/system. Не путать номер сообщения с номером реплики оператора. Исходное время не заменять относительным без явной проверенной привязки аудио.
9. Цитаты могут содержать персональные данные. Заполненные формы, транскрипты и подписанные аудиоссылки хранить локально и не публиковать/коммитить. Доступ к аудио ещё не проверен. Не оценивать интонацию или дикцию по одному транскрипту.

Модель, исследовательский каталог примеров и сходство с соседним сценарием не являются источниками GT. Каталог сообщает факты и вопросы; готовых меток в нём нет.
