CQA — контрольные примеры для будущего реального прогона

Это 17 искусственных диалогов и 18 частичных ожидаемых ответов, составленных AI
по явным правилам чек-листа. Они не являются ручной разметкой DEV, официальным GT,
результатами модели или независимым отложенным тестом. Использовать для разработки.
Казахские формулировки до языковых выводов должен проверить носитель.

Назначение:
— проверить приветствие оператора отдельно от бота;
— различать N/A и пропуск обязательного действия;
— проверить порядок идентификации и раскрытия;
— сопоставлять консультацию с переданным тестовым справочником;
— проверять закрытие и явный обрыв;
— не приписывать оператору оскорбления клиента;
— заметить предложение частной услуги независимо от согласия клиента;
— применить новый критерий из конфигурации;
— проверить один пример инструкции атакующего внутри транскрипта.

Для каждого кейса заданы только однозначные целевые критерии. Остальные значения
не придуманы и не заполнены автоматически. Тестовые справки вымышлены и не описывают
настоящие тарифы или процедуры Freedom Broker.

Подготовка запросов из корня проекта:
node research/readiness-cases/prepare.mjs

Команда использует текущие сборщики prompt/schema, сохраняет подготовленные входы
в prepared/ и проверяет их структуру. Никаких API-вызовов и денежных расходов нет.
Отчёт об успешной подготовке НЕ означает, что модель ответила правильно.

В prepared/requests.json поле expected — локальная проверочная информация.
При реальном вызове отправляются ТОЛЬКО messages и response_format плюс явно
настроенные model/provider параметры. expected, case_id и review_note модели не
передавать. Для транскриптов используются нейтральные ID readiness-001 и далее.

После появления API реальные ответы надо отдельно валидировать штатным кодом,
сравнить по перечисленным критериям и вручную проверить достаточность доказательств.
Не требуйте одну-единственную эталонную цитату, если другое основание тоже достаточно.
Сохраняйте отказы/неопределённость, количество вызовов, usage, задержку и стоимость.

Для окончательного сравнения моделей используйте отдельную ручную разметку реальных
диалогов и заранее зафиксированное разделение. Эти искусственные случаи не заменяют её.
