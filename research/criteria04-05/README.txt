Диагностика 04 и 05 без подмены PDF новыми требованиями

Источники: все три страницы исходного чек-листа; принятые уточнения организатора;
решение пользователя не вводить потолок баллов за эскалацию и обязательные извинения.
Текущая интерпретация пользователя для 05 сохранена отдельно в interpretations.json.
Оценка 20 для реального RU — вывод ассистента после разбора, не прямая человеческая
разметка и не официальный Ground Truth. Казахские примеры требуют проверки носителем.

План заморожен до просмотра результатов:
1. Baseline 1.3: четыре пары по два повтора, два контроля и два знакомых DEV-чата.
   20 реальных вызовов. Ожидания пар не передаются модели.
2. Менять инструкции только при воспроизведённой содержательной ошибке. При отсутствии
   оснований сохранить действующий промпт. При изменении — те же 20 вызовов candidate.
3. Отдельно четыре новых формулировки и два новых рабочих прогона чатов из pilot20:
   p1-ru-026, p1-kz-003. Шесть вызовов. Содержимое синтетики известно автору, поэтому
   это проверка переноса, не слепой независимый тест. Зарезервированный holdout10 не трогаем.
Итого 26 вызовов без изменения или до 46 при наличии кандидата. Одновременно не более
двух, один вызов на оценку, без автоматических повторов и ремонта ответов.

Состояния failed/unresolved не прячутся и не заменяются старым успешным ответом.
Практическая помощь без извинения в KZ изначально сохранена без ожидаемого вердикта:
полученную во время работы трактовку пользователя оцениваем отдельно, не переписывая
замороженный файл cases.json, запросы или ранее сохранённые результаты.

Подготовка без API:
node research/criteria04-05/run.mjs --stage=baseline
node research/criteria04-05/run.mjs --stage=holdout

Реальные вызовы из корня проекта с существующей .env:
node --env-file=.env research/criteria04-05/run.mjs --stage=baseline --live
node --env-file=.env research/criteria04-05/run.mjs --stage=candidate --live
node --env-file=.env research/criteria04-05/run.mjs --stage=holdout --live
Команда candidate требует, чтобы промпт отличался от baseline. Команды не перезаписывают
предыдущие живые запуски. Baseline 1.3 — история эксперимента, не команда для запуска
после будущего изменения версии промпта.

Данные эксперимента отдельно от рабочей истории: data/criteria04-05/.
Сохраняются снимки запросов, схем, ответов без ключей/заголовков, usage, фактов,
всех восьми критериев, точных источников и исходного подсчёта. Автоматического
развёртывания или перезапуска работающего сервиса нет.

Выполнено:
— Baseline: 20 вызовов, 20 принятых; 16 совпадений с замороженными ожиданиями,
  четыре диагностических результата без заданного эталона. 19 полных, 1 частичный.
— Трактовка пользователя для практической помощи по 05: Да/Да, отдельно от статистики
  замороженных ожиданий. Игнорирование проблемы: Нет/Нет.
— Перенос: 6 вызовов, все приняты. Четыре новых искусственных случая совпали с
  ожиданиями автора; ещё два реальных пилотных чата оценены без экспертных меток.
— p1-ru-026: 04=5, 05=Нет; p1-kz-003: 04=20, 05=Да.
— В реальном p1-ru-010 теперь 04=10 против прежних 20. Обоснование ссылается на
  запрошенное оператором, но не полученное название бумаги. Это спор о достаточности
  следующего шага, а не доказанная ошибка или основание принудительно выставить 20.
— Контроль неизвестной договорной комиссии: unresolved только по 04, остальные
  семь критериев разрешены, полный итог null. Неизвестное не превращено в N/A.
— Системный промпт и рабочие инструкции критериев НЕ менялись: кандидат не оправдан
  результатами. Провайдер остался на версии 1.3, прежняя история не переписана.
— Аудит 26 записей: 343 цитаты критериев и 77 диапазонов проверены; отдельно проверены
  все dialog_facts, исходные сообщения, сырые ответы, usage и расчёт баллов.
