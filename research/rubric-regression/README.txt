Микро-набор для проверки интерпретации рубрик

Пять искусственных сценариев из обсуждения; не официальный Golden Set и не
независимая экспертная разметка. Ожидания созданы ассистентом. KZ-текст требует
проверки носителем. В кейсе 05 (Bench-03) ожидаемый ответ намеренно не задан:
обязательное вербальное сочувствие не установлено PDF. Его ответы измеряются
как диагностика и не включаются в утверждения о совпадении с эталоном.

Bench-02 содержит явное указание, что отсутствие названия блокирует проверку
позиции. Ожидание 10 относится только к этому сценарию. Оно не вводит универсальный
потолок 10, обязательный номер счёта или набор реквизитов для любой эскалации.

Подготовить входы без вызовов API:
node research/rubric-regression/run.mjs

Выполнить 3 реальных прогона каждого из пяти кейсов (15 платных вызовов):
node --env-file=.env research/rubric-regression/run.mjs --live --repeats=3

Модель, лимит и endpoint берутся из текущей .env. Нет повторов при ошибке,
скрытого fallback или готовых ответов. Каждый случай отправляется отдельным
вызовом через рабочий провайдер. Полный ответ проходит обычные проверки фактов,
цитат и критериев. В модель не передаются expected, basis или описательный ID.
Неопределённость, несовпадения и сбои записываются отдельно, с usage всех попыток.
Результаты и снимки оценок сохраняются в приватном data/rubric-regression/.
При несовпадении, неопределённом ответе на размеченный целевой критерий или
техническом сбое live-команда завершится с ненулевым кодом. Диагностический
Bench-03 без эталона не считается ни совпадением, ни семантическим провалом.

Три одинаковых ответа — лишь наблюдаемое согласие на трёх запусках; это не
доказательство 100% стабильности. Набор знакомый, малый, не измеряет обобщение.
Скрипт не меняет рабочий промпт, результаты DEV, оценки в интерфейсе и не
развёртывает изменения автоматически.

При следующем изменении промпта приоритет проверки — применимость по текущему
правилу N/A до оценки качества. Условие достаточности исходных данных должно
учитывать весь контекст до первого ответа человека, включая сообщения бота.
Это толкование следует зафиксировать отдельно и согласовать с проверяющим.
