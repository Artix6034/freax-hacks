Очередь доступна в интерфейсе после загрузки набора и через CLI:

npm run evaluate:batch -- resume --run-id 608e0e6b-72f4-4ea6-b34f-3c1bbaa04704

Одновременно работает один пакетный прогон на рабочий каталог, в том числе между
CLI и сервером. Системная блокировка автоматически снимается при падении процесса.
Пауза дожидается текущих запросов. Продолжение пропускает сохранённые completed,
partial и failed. После аварии готовая запись принимается без нового вызова;
неизвестная прерванная попытка сохраняется как failed. Для явного повтора сбоев:
npm run evaluate:batch -- resume --run-id RUN_ID --retry-failed
Это новые оплачиваемые вызовы, старые попытки сохраняются. Автоповторов AI нет.
После изменения модели/промпта/схемы/справки создаётся новый прогон.

Исправление Windows: атомарная замена JSON может временно вернуть EPERM/EACCES/EBUSY
при чтении файла. Повторяется только операция переименования (до 8 попыток, около
1,6 с ожидания суммарно). Прежний целый JSON не удаляется. Повтор AI не выполняется.
При постоянной ошибке очередь останавливает запуск новых заданий.
