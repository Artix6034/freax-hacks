Freedom Broker CQA: выбор конкретных моделей для эксперимента
Дата проверки источников: 7 ноября 2026. Это исследование моделей при уже определённых архитектурах. Сравнительных CQA-замеров и победителя по точности пока нет. Рабочее приложение не изменялось, платные inference-вызовы и загрузка весов не выполнялись.

Предлагаемый небольшой набор: gpt-6-astra и claude-fable-5-1 как кандидаты финального судьи разных семейств; gpt-6.1-sol как более дешёвый финальный судья/контроль анализатора; gpt-6-luna как дешёвый fragment analyzer; Unbabel/M-Prometheus-7B как специализированный генеративный judge; jev-1.14.0 как специализированный typed-decision judge с отдельным evidence extractor. Начинать с Luna -> Sol и контрольного полного Astra. Это приоритет запуска по совместимости и цене, а не рейтинг точности. Для CPU event branch: TF-IDF + LogisticRegression, затем text-embedding-3-large + LogisticRegression при достаточных event labels.

Новые критерии задаются полным правилом, allowed_values, описаниями ступеней и NA condition из checklist snapshot. Schema подтверждает только форму. Prompt injection и ложная предварительная оценка не объявлены решёнными ни у одного кандидата.

OpenAI API/schema актуализированы через Context7. Refusal, length, incomplete, ошибка парсинга или решающий неизвестный факт -> технический failed/unresolved с причиной, не no/NA/нулевой балл. Источники: https://developers.openai.com/api/docs/guides/structured-outputs ; https://developers.openai.com/api/docs/guides/reasoning . Для Fable/Argon нужен native adapter либо проверенная compatibility поверхность. Для Fable отдельно учесть текущие правила хранения Covered Model; это не ZDR по умолчанию: https://platform.claude.com/docs/en/manage-claude/api-and-data-retention .

5. Jev и Decider: релевантны по устройству, но не заменяют evidence pipeline

TypeSafe Jev подтверждён официальными docs; открытые веса или первичная публикация архитектуры/RLCD в проверенных first-party материалах не найдены. SDK/repo клиента не раскрывает веса. Подключение: POST https://api.typesafe.ai/v1/systemone, поля model/state/questions. Действующие pinned IDs jev-1.13.0 и jev-1.14.0;1.14 выпущен 14.10.2026, vendor заявляет улучшение multilingual. Цена обоих $0.042/M input, output free; default64K per request и 32K per question. Experimental long context262K выключен по умолчанию, в первый опыт не включать. Источники: https://docs.typesafe.ai/models ; https://docs.typesafe.ai/changelog ; документация получена также через Context7.

Для CQA использовать Choice с ключами, однозначно отображаемыми кодом в allowed_values, и полными описаниями вариантов. 04: отдельные 0/5/10/15/20, 06:0/4/7/10; na добавлять только где разрешён и только с его точным условием. Choice может выбирать из нового набора без retraining. Noul даёт P(yes), но у 02/03/07 не заменяет applicability, а 08=yes означает нарушение, не выполнение. Score возвращает математическое ожидание по уровням, иногда дробное: округлить его в ближайший допустимый балл — новая недоказанная политика, поэтому primary эксперимент использует Choice. Упорядоченность ступеней передаётся описаниями, не придуманным интерполированным баллом. https://docs.typesafe.ai/primitives/choice ; https://docs.typesafe.ai/primitives/score .

Технический unresolved/недостаток предметного reference хранится вне официального значения критерия; он не превращается в na. В typed question можно отдельно проверить достаточность информации, а отсутствие нужных фактов/поддержки отправляет на review. Пороги confidence выбираются только на train; вероятность/peaked distribution не доказательство калибровки именно на KZ CQA. Jev не делает сложную арифметику, сравнение времени или многошаговую косвенную логику надёжной по определению. В docs указаны literal-reading, option-order, large-state и adversarial риски: https://docs.typesafe.ai/model-jaggedness .

Цитату Jev не генерирует. Общий для сравниваемых final judges extractor сначала строит event ledger с точными spans/omission anchors без предварительного final score. Jev получает полный оригинал + тот же журнал + рубрику/reference и выбирает оценку; можно отдельно выбирать event IDs из уже извлечённых кандидатов. Объяснение показывать с provenance: событие извлекла Luna/другая модель, вердикт вынес Jev. Если доказательство не поддерживает label или отсутствует существенный candidate, строгий completed review не формировать. Нельзя просить другую LLM сочинить удобную цитату после выбора Jev и называть её подтверждённой им. Для пропущенного действия сохраняются ожидаемое место и просмотренный source range, а не цитата отсутствия.

Perplexity — полезная найденная альтернатива: актуальные pplx-decider-v1.2 (27B,$0.02/M) и pplx-decider-flash-v1.2 (4B,$0.01/M), output free, context256K, POST https://api.perplexity.ai/v1/decisions. Оба typed, объяснений не пишут. Для восьми вопросов обычный v1.2 биллит state один раз на группу; Flash повторно для каждого вопроса и может оказаться дороже. У v1.2 grouping влияет на решения — состав questions фиксировать. Web grounding в нашем опыте выключить: reference должен быть одинаковым и версионированным, поисковые расходы не нужны. https://docs.perplexity.ai/docs/decisions/quickstart ; Context7 подтвердил API и billing.

Критический version caveat: текущие запросы с именем pplx-decider-v1.1-27b перенаправляются в v1.2, а поле response.model повторяет запрошенное имя. Просто логировать это поле недостаточно для воспроизведения старого benchmark. Хранить дату/docs snapshot/provider version metadata, не объявлять старый result1.1 измерением 1.2. Источник: та же официальная страница, Model names. 7. JEPA: что подтверждено и почему не входит в первый набор

I-JEPA — Image-based Joint-Embedding Predictive Architecture, CVPR2023, официальная реализация https://github.com/facebookresearch/ijepa . V-JEPA — video representation learning, https://github.com/facebookresearch/jepa . Они обучают предсказание представлений частей visual input; роли сообщений, чек-лист и текстовые quotes не являются их готовым интерфейсом. Название JEPA не даёт им способности быть текстовым judge.

LLM-JEPA — Hai Huang, Yann LeCun, Randall Balestriero; arXiv2509.14252v2 от 07.10.2025, https://arxiv.org/html/2509.14252v2 . Это дополнительная embedding-space objective для fine-tuning/pretraining LLM при сохранении генеративной цели. Работа изучает NL-RX/GSM8K/Spider и sentiment, а не CQA/NA/выделение доказательств. Первичный code link из paper перенаправляется к авторской реализации https://github.com/galilai-group/llm-jepa ; это не случайный похожий fork. Для больших моделей repo прямо предусматривает GPU training; готовый hosted CQA endpoint не подтверждён.

Вывод не "JEPA бесполезна для текста": текстовая адаптация существует. Но чтобы использовать её здесь, потребовались бы выбранный обученный checkpoint, дополнительная CQA/event head или judge adaptation, данные, обучение и проверка, а также генеративный интерфейс объяснений/источников. Им могла бы быть та же адаптированная LLM: отдельная вторая модель не обязательна, но сама JEPA objective готового CQA-контракта не предоставляет. При API-first и 65DEV это отдельный исследовательский проект. Не включать JEPA как будто это взаимозаменяемая альтернатива gpt-6-astra или Jev. Semantic Tube Prediction в том же author repo — ещё обучающий метод; не самостоятельный безобучаемый judge.

9. Список для реального теста и три предварительных комплекта

Основной shortlist на train, затем заранее сократить test:
1) gpt-6-luna — cheap extraction baseline; проверить event recall/цитаты против Sol, не считать достаточной по цене.
2) gpt-6.1-sol — основной balanced final baseline, допустим тот же model family для обоих stages.
3) gpt-6-astra — более дорогой final control, нужный чтобы измерить, покупает ли цена качество.
4) claude-fable-5-1 — final candidate другого семейства; отдельный adapter и бюджет.
5) Unbabel/M-Prometheus-7B через Featherless — основной специализированный генеративный challenger, включён из-за DA+multilingual evidence, а не слова judge.
6) jev-1.14.0 — typed challenger; общий evidence extractor, bounded Choice и отдельные ограничения. Train version check1.13.0 по возможности, не плюс бесконечное число версий в test.

Reserve: Selene Mini как альтернативный generative specialist с финансовыми expert labels, но слабым обоснованием RU/KZ; Decider1.2 как дешёвый typed резерв с version-routing caveat; Argon как третье семейство. Не все reserves одновременно. Если M-Prometheus не проходит train contract/language gate, до freeze заменить его на Selene и честно отметить, что KZ всё ещё неизвестен. Не выбирать замену после просмотра test outcomes.

Комплект | Analyzer -> final | Почему проверить | Известная цена и неопределённость
Приоритет максимальной точности | Sol -> Astra; отдельный blind Fable review на заранее заданных случаях или на всём research test | Больше бюджета на extraction/reasoning, возможность выявить разногласия | Это цель, не доказанное максимальное качество; disagreement разрешает человек/заранее заданный review процесс, баллы двух судей не усреднять

Специализированный judge и универсальная модель могут быть одинаково полезны в разных ролях. Здесь нет собственного выдуманного рейтинга 0–100 пригодности. "Первый/резерв" — наше предварительное инженерное суждение по типу задачи, языковым доказательствам, output contract и реальному API, а не агрегированный benchmark score.

Стоимость полного pipeline, только иллюстративные допущения для сопоставления: на proposed test19 диалогов/33chunks; chunk3Kinput+3Koutput, финал 8Kinput+6Koutput, output включает reasoning. Ни эти длины, ни latency не измерены, это не верхний spending limit.
— Sol -> Astra:33*$0.036 +19*$0.38 = $8.408; с 19 независимыми Fable reviews ещё$7.22, всего$15.628 при тех же допущениях и без extra adjudication calls.
— Luna -> Sol:33*$0.0018 +19*$0.076 = $1.5034.
— Luna -> Luna:33*$0.0018 +19*$0.0038 = $0.1316.
— Luna -> Jev: extractor$0.0594 +19*(8000/1M*$0.042)=$0.065784 за label stage с extractor, БЕЗ дополнительных explanation/recovery/fallback calls. Это не полноценный доказанный комплект: все final evidence должны уже быть поддержаны, иначе extra review/failed.
— Luna -> Decider1.2: те же extractor +19*$0.00016 = $0.06244; Flash при 8 вопросах биллит state8 раз, поэтому не автоматически дешевле.

Не выдавать низкую цену typed labels за стоимость готовых evidence/explanations. Реальный total = extraction+judge+review+embedding+retries/repair+account overhead; все failure/fallback calls учитываются. На коротком DEV один C0 может быть дешевле сложного hybrid. Фактический inference spend этого исследования $0.

10. Сопоставимый эксперимент A/B/C/D

Сохраняется proposed group-aware split research/sequential-study/split-70-30.proposed.json:46train/19test (70.77/29.23%), seed cqa-sequential-group-split-v1|2026-11-07. Все fragments одной беседы и близкие multilingual-сценарии вместе;16 предложенных family groups, train9/test7. Test RU10/KZ4/EN5,18chat/1voice. Группы требуют независимой проверки ДО freeze; exact/normalized/digit-template совпадений не найдено, но полная сертификация semantic duplicates не выполнена. Старое pilot20/holdout10 разбиение не смешивать с новым. DEV уже изучался — этот test внутренний, не официальный неизвестный контроль 10 организаторов.

Сначала выбрать модели при фиксированной архитектуре, потом архитектуры при фиксированном judge:
M1 final-model comparison на train: один полный original + одинаковые rubric/reference/schema, без предварительных вердиктов, Sol/Astra/Fable. Выбор prompts/settings и language gate только train.
M2 comparable role для generative specialists: тот же complete input/schema для M-Prometheus, при необходимости train-only faithful native-format ablation. Если нужны individual-criterion calls, повторить такой же режим у общего judge; не приписывать эффект 8 вызовов самой модели. Никакого тихого strong-LLM repair.
M3 typed role: общий закэшированный Luna evidence-first ledger без scores + полный original, одинаковый для Jev, generic judges и выбранного generative specialist. Labels и evidence quality учитывать раздельно, но completed valid review требует оба. Jev не штрафовать за отсутствие заявленной генерации как будто он обещал её; весь pipeline считать по реальному контракту и цене.
После train freeze: A=выбранный generic full judge; B=Luna sequential -> тот же final; C1=тот же extractor/fulltext -> Jev, C2=generic specialist в сопоставимом режиме; D=CPU event detector -> тот же generic final, только после event supervision. Минимальный test можно сократить до A/B/C1 и одного заранее выбранного C2; D остаётся blocked по отсутствию labels, а не заполняется выдуманными метриками.

Общий контроль критериев:
— В train добавить реальные человеческие verdict labels и event/span coverage; test19 размечают независимо 2 оценщика с adjudication/уточнением спорных правил, не показывая outputs систем. Пока этого нет, accuracy-run не выполнен.
— TF-IDF/IDF/scalers/features/class weights/calibration/thresholds/MLP settings только inner train folds по семействам; few-shot только train. Frozen pretrained embeddings на test вычисляются после freeze без использования test labels. Pipeline fit не на всех 65.
— При новом критерии generic/typed prompts обновляют вопросы и allowed options без обязательного retraining; fixed supervised classifier для нового target имеет LLM fallback. Изменить criterion04 на binary, добавить произвольный NA или новые policy правила нельзя.
— Одинаковые исходный checklist/reference/test, source hashes, grouping, model/provider settings, per-stage limits и parser/failure policy. Endpoint/quantization фактической модели фиксировать. Нет обещания bitwise reproducibility API.
— Preregister boundary budgets8/12/20 и изменение состояния; при сравнениях судей использовать одинаковый cached ledger. H_hidden/H_visible с одинаковыми candidates отдельно измеряет sensitivity к classifier hints. Не давать судье label из gold/AI annotation.
— Диагностики: роль bot/operator, идентификация в раннем chunk, disclosure до подтверждения, несколько вопросов, late correction, явное ожидание/обрыв, NA vs pending; adversarial transcript instruction и ошибочный предварительный score. Synthetic RU/KZ/EN cases заранее регистрируются отдельно от natural accuracy; KZ варианты проверяет носитель. Никакого избирательного исправления prompts по test.

Метрики итогов: exact accuracy/macro-F1/confusion отдельно по каждому criterion (с allowedNA), falseNA/missedNA,08precision/recall с positive support, totalMAE/RMSE/bias с paircount и completion, RU/KZ/EN отдельно. Missing predictions остаются ошибкой завершения, null reference исключается perlabel, не заменяется no. MAE только валидных пар обязательно рядом с completion и сравнением на общем пересечении.

Evidence: code existence/substring/ID/range/time/role; human span/messageID localization P/R и expert sufficiency отдельно; correctness of tariff/procedure по версионированному предметному reference. Exact quote не подтверждает factual truth. Timestamp серверный исходный, ISO не audio offset без mapping. Специально измерить evidence extraction recall до final score, unsupported quotes после финала, исправления/искажения судьи и устойчивость к границам.

Latency: end-to-end p50/p95, все call counts/stages, queued/coldstart/retries/fallback/CPUfit+predict/embedding отдельно; при n19 p95 крайне нестабилен. Cost: actual usage/cached/reasoning/output и тарифная версия плюскомиссии/подписка; модельная probability не наша calibrated accuracy. Paired uncertainty по семействам; при 7testfamilies,4KZ и 1voice небольшие разницы не объявлять статистически надёжной победой. Официальная формула отбора top50 не раскрыта — наша сводка не является официальным рейтингом.

11. Практическое подключение к существующему Node приложению

Текущее приложение уже имеет A1 schema/transport, validation цитат и checklist enums, калькулятор и original/final appeals. В рамках исследования оно не изменялось. Предлагаемые следующие изменения, после доступа/бюджета:
1) Сохранить A1 full как control; добавить pipeline ID и отдельные модели analyzer/final в конфигурации. Для одной модели разрешить одинаковый ID, без обязательного второго провайдера.
2) Добавить source-preserving chunker, deterministic reducer и state/ledger из предыдущего контракта. Сначала artificial tests, затем реальные train с human review. Stage output не содержит weighted totals.
3) OpenAI-compatible specialists через https://api.featherless.ai/v1/chat/completions, точный case-sensitive HF model ID; не отправлять OpenAI reasoning_effort не-OpenAI модели. Не считать advertised structured text strictJSON гарантией; protocol capability/schema support проверяется smoke. Endpoint32K/4K важнее общего modelcard128K. Без молчаливой truncation.
4) Jev adapter отдельный /v1/systemone, state/questions, typed decoder; Decider отдельный /v1/decisions. Это не тот же /chat/completions. Генерировать choices из snapshot; final_value только allowed enum, не ожидаемый Score. Model response ошибки/недостающие answers/probability shape/отсутствующий required support -> failed/review, не default no.
5) Shared evidence extractor формирует дословные sources прежде финала. Label judge не получает уже выбранные оценки. Причины и provenance хранятся отдельно. Для N/A требуется основание из правила, для omission — expected_at и range; final stage всегда получает полный original. Не указывать автором объяснения Jev, если его сгенерировала другая модель.
6) Telemetry: requested_model, returned_model, resolved_version_known/unknown, endpoint/provider routing, quantization/runtime context, дата документации, prompt/schema/checklist/reference/split hashes; usage всех calls и failures. Decider response может повторять model name, поэтому returned_model не равен доказательству неизменных весов.
7) CPU classifier/GLiNER sidecar только опционально: веса и пакеты установить позднее в согласованной реализации; сейчас они не загружались. Event taxonomy и thresholds версионируются; неподдерживаемый новый criterion проходит через LLM.

Context7 использован для TypeSafe, Perplexity, Featherless, OpenAI и GLiNER; официальные model cards и papers — для назначения моделей и benchmark metadata. Дополнительный framework не обязателен: Node fetch может обслужить transport, existing code — валидацию и расчёт. Проверенный broker reference нужен для решающих продуктовых фактов; ни одна model card его не заменяет.

12. Факты, гипотезы, неизвестные

Подтверждено: указанные проекты существуют и имеют разные output/task contracts; Jev/Decider typed и не пишут prose; Score допускает дробные expectations; M-Prometheus/Prometheus/Selene имеют absolute grading; pairwise agreement — иной target; API-продукт Patronus retired; Featherless предлагает часть open judges без нашего GPU; актуальные Decider names могут перенаправляться на новые версии; ручного GT в проверенных артефактах нет.

Наши предварительные гипотезы: Luna -> Sol окажется разумным balanced baseline; Astra/Fable могут улучшить сложные 03/04/07; M-Prometheus может превзойти English judges на RU; Jev/Decider могут удешевить bounded label stage; GLiNER/encoder classifier может помочь локализации. Ни одна из этих гипотез не выдаётся за измерение или доказанное KZ превосходство.

Неизвестно: сравнительная CQA accuracy всех кандидатов, KZ и code-switch recall, реальная достаточность цитат и ошибки N/A, прирост от двух моделей, эффект runtime FP8 против BF16, доступ аккаунта, фактические cost/latency, число дополнительных evidence/fallback calls, точные N некоторых авторских подвыборок. Это ограничивает рейтинг, но не мешает выбрать конкретный небольшой набор для честного теста.

Прямой вывод: наиболее непосредственно соответствуют изменяемому CQA генеративные rubric judges и instruction-following LLM; Jev/Decider подходят для конфигурируемого bounded grading при отдельном evidence pipeline. Encoders/GLiNER полезны как поиск/извлечение/признаки. Scalar reward, pairwise-only демонстрации и visual JEPA не заменяют финальную абсолютную оценку по чек-листу с N/A и доказательствами только потому, что называются critic/judge/intelligence. Победителя определит сопоставимая человеческая проверка, которой пока нет.
