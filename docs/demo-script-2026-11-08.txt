Freax — короткая техническая демонстрация

Слайды 1–2, 90 секунд
«Freax оценивает диалог по текущему чек-листу. Каждое решение связано с точной репликой или проверенным диапазоном. Фронт — HTML/CSS/JS, сервер — Node.js 24. Один вызов возвращает общие факты и оценки; сервер проверяет формат, цитаты и считает баллы. Ключ остаётся на сервере».

Слайд 3 и живое приложение, 90 секунд
Загрузить сохранённый DEV без новых вызовов. Выбрать существующую карточку. Показать N/A, обычный ответ и источник. Нажать цитату — соответствующая реплика выделится в транскрипте. Показать соседний контекст. Открыть «Подать апелляцию»: обоснование, исходная оценка, отдельное решение проверяющего. Для сохранения использовать изолированный тестовый стенд, а не оригинальные DEV-оценки.

Слайд 4, 60 секунд
Открыть «Чек-листы». Показать инструкции, веса, ступени и разрешённый N/A. Новая версия не меняет историю. Если добавлен критерий вне официального формата, приложение это поддерживает, а экспорт сообщает несовместимость.

Слайд 5, 45 секунд
«Для Dynamics 365 подготовлен HTML-компонент и JavaScript формы. Форма передаёт транскрипт, аналитик запускает оценку, а компонент возвращает сводку с ID, статусом и версией правил. Обмен проверяет точный origin и окно отправителя. Ключ модели остаётся на сервере». Это подготовленный адаптер, подключение реального tenant показывать только после реальной настройки.

Слайд 6, 45 секунд
«История хранит исходную оценку и решения проверяющего раздельно. Пакетная очередь сохраняет прогресс, продолжение использует готовые попытки. Выгрузка JSON 1.0 проходит проверку формата, цитат и арифметики. 85 автоматических тестов покрывают эти механизмы». Показать историю и пакетную очередь, не запускать снова все 65 DEV. Затем перейти к живому продукту и вопросам.

Оставить 2–3 минуты на вопросы. Ответы по существу:
— N/A перераспределяет вес по правилам чек-листа, unknown остаётся частичным.
— Грубая ошибка — отдельный флаг, не автоматическое обнуление.
— Исходный AI и ручной пересмотр хранятся раздельно.
— Нет официального GT, знакомое DEV-согласие не называем точностью.
— Файловое хранилище рассчитано на один процесс, масштабирование требует общей БД/очереди.
