Продолжение после прерывания:
node --env-file=.env scripts/prepare-prod.mjs --resume
Готовые completed/partial/failed попытки не оплачиваются повторно.
Отдельный явный повтор только технических сбоев создаёт новые оплачиваемые попытки:
node --env-file=.env scripts/prepare-prod.mjs --resume --retry-failed

Что делает запуск:
1. Проверяет действующий чек-лист и формат приложения Results.
2. Принимает только ровно 10 уникальных ID, только чаты, с репликами оператора.
   DEV65, дубли и звонки отклоняются до создания AI-провайдера и платных вызовов.
3. Фиксирует исходный набор, версию/хеш промпта и чек-лист в data/prod/.
4. Использует активную 1.6.1 через существующие server provider, очередь и валидаторы.
   Экспериментальная 1.6.2 с найденной отложенной регрессией не подключается.
5. Оценивает с параллельностью 4; автоматического повтора AI нет.
6. Проверяет готовность, атомарно экспортирует и затем повторно валидирует JSON.

По приложению:
— исходные conversation_id и номера реплик сохраняются;
— 8 критериев, true/false для логических, null только для разрешённого N/A;
— шкальные значения передаются исходными ступенями, без усреднения;
— score округляется HALF_UP, грубый флаг не обнуляет итог автоматически;
— partial/failed экспортируются как status=error, criteria=[], score=null с причиной;
— один согласованный run, модель/промпт/справка не смешиваются;
— имя команды Freax, модель берётся из реальных метаданных провайдера.

Код выхода 0 после оценки означает prod_ready. Код 2 и exported_with_errors
означают: файл структурно валиден, но содержит частичные/неуспешные оценки;
их нужно честно сохранить или разбирать по разрешённым источникам организатора.
Отсутствующие сведения не подменяются нулём или N/A.

Локальные AI-настройки и адрес API сохранены в игнорируемом Git файле .env.
