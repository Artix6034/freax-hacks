ЧТО СДЕЛАНО

Единая проверка структуры JSON 1.0 используется браузером, экспортёром и CLI.
src/web/submission-compatibility.js — общие коды, типы, шкалы и причины отказа.
Экспортёр по-прежнему отвергает несовместимые версии, а не пересчитывает шкалы
и не удаляет критерии. Формат официальных результатов не изменён.

В интерфейсе:
— Видна совместимость сохранённой версии до оценки одного диалога/набора.
— В редакторе отдельно проверяется черновик. Изменение черновика не меняет
  предупреждение выбранной сохранённой версии до сохранения.
— Обычные изменения текста/веса допускаются; смена типа, числовой шкалы,
  добавление, удаление или переименование исходного ID объясняются заранее.
— Несовместимый чек-лист можно сохранить. Перед оценкой в UI требуется
  отметка понимания, что результаты доступны в приложении, но не в официальном JSON.
— При смене выбранной версии отметка сбрасывается.
— N/A, разрешённое чек-листом, но не форматом (например, contact в звонке),
  показано как потенциальный error конкретного диалога, а не запрет всего чек-листа.

CLI без модели:
  node scripts/evaluate-batch.mjs preflight --checklist config/checklist.organizer-2026-11-07.json

Перед start/resume CLI также выводит результат проверки. Несовместимая версия
по умолчанию останавливается до вызовов модели. --allow-incompatible явно
разрешает только экспериментальную оценку; экспорт это разрешение не обходит.
HTTP API остаётся универсальным для динамических критериев; сама проверка экспорта
обязательна на сервере. Клиенты API должны показывать собственные предупреждения.

RAG для нескольких коротких фактов не требуется. В createApp уже поддержаны
CQA_REFERENCE_FILE и CQA_REFERENCE_VERSION; buildMessages передаёт содержимое
в verified_reference отдельно от checklist и conversation. Подключение меняет
reference_hash/configuration_hash и требует нового прогона.

Это справочные утверждения, а не новые условия оценки. Не помещать их в шкалу
04 и не обучать оценщик на ID DEV. Проверка применимости должна предшествовать
использованию: компания, продукт, канал/версия, период. Сейчас подтверждения
применимости к каждому из этих пяти чатов не получены, загрузки в runtime нет.
Текущая просьба пользователя «как их засунем без RAG» разъяснена этим механизмом;
она не трактуется как подтверждение истинности/применимости всех кандидатов.
